ghstars 使用指南

把 GitHub 星标变成本地可检索的知识库 —— 命令行、MCP、skill 三入口，一份内核。

版本 v0.1.0 更新 2026-10-20 Python ≥3.11 依赖 零第三方 Windows 已实测 · macOS/Linux 设计支持
这份文档解决什么

你的收藏已经躺在本地知识库里。这份指南讲清三件事： ①怎么用最快的方式查到「我收藏过什么」；②三种入口（CLI / MCP / skill）分别装在哪、怎么调； ③以后改了代码或换了 Agent，怎么维护。命令示例都是通用写法，把路径换成本机的即可。

目录

① 30 秒上手 ② 它是怎么搭起来的 ③ 三个入口：CLI / MCP / skill ④ 装在哪、文件在哪 ⑤ 命令速查 ⑥ 六个日常场景 ⑦ 维护与升级 ⑧ 排错

① 30 秒上手

ghstars doctor                 # 自检：token / 目录 / 索引 / LLM 是否就绪
ghstars search "视频制作"       # 查你 star 过的项目
ghstars stats                  # 看总量与分类分布

输出形如：

「视频制作」命中 3 条

1. acme/video-kit   ★1234   [tools-utilities]   rel=4.2
   把长视频自动切成短视频并批量导出…
   tags: 视频剪辑, 自动化剪辑, 短视频制作
   <你的笔记目录>/github-stars/tools-utilities/acme-video-kit.md
rel 是排序分，不是质量评分：标签精确命中约 4.95，长描述里顺带出现约 1。 用来判断「为什么这条排在前面」很方便。

② 它是怎么搭起来的

Markdown 文件唯一权威数据源，Obsidian 直接读
→
ghstars 内核拉取 / 分类 / 中文标签 / 打分
→
SQLite 索引派生缓存，删了能重建
CLIghstars search …
任何能跑命令的 Agent
MCPghstars mcp
Claude / Codex / Hermes / Cursor
SkillSKILL.md
教 Agent 何时调 CLI

关键设计：三个入口都是薄壳，逻辑只有一份。所以不会出现「命令行能查到、MCP 查不到」这种漂移。 Markdown 是权威源 —— 索引坏了、机器换了，ghstars index 重建即可，数据不丢。

③ 三个入口：CLI / MCP / skill

CLI —— 最大公约数

ghstars search "简历 优化" --json
ghstars get owner/name --full
ghstars search "小红书" -n 20 --category xiaohongshu --json

所有命令加 --json 都能拿到结构化结果；进度日志走 stderr、结果走 stdout，可以直接 | jq 或交给 Agent 解析。

MCP —— 给支持 MCP 的宿主用

服务器就是 ghstars mcp（stdio），暴露 5 个工具：

工具作用
stars_search按中文场景词/项目名/技术词检索收藏
stars_get按 owner/name 看单个项目
stars_stats总量、归档数、分类分布
stars_sync同步最新 star（有副作用，支持 dry_run）
stars_reindex手工改过文件后重建索引
Hermes 
mcp_servers:
  ghstars:
    command: "ghstars"
    args: ["mcp"]
    timeout: 120

已写入本机 llm-wiki profile，重启 Hermes 后出现在工具列表（前缀 mcp_ghstars_）。

OpenCode / Claude Code / Cursor 
// opencode.jsonc / ~/.claude.json
"ghstars": {
  "type": "local",
  "command": ["ghstars", "mcp"]
}

OpenCode 已写入全局配置（~/.config/opencode/opencode.jsonc），重启生效。

Skill —— 教 Agent「什么时候用」

安装位置：

宿主路径
Claude Code~/.claude/skills/ghstars/SKILL.md
Codex~/.codex/skills/ghstars/SKILL.md

已装好。以后改了话术，一条命令同步到所有宿主：

cd D:/Tools/ghstars
python scripts/sync_skill.py          # 自动探测已存在的宿主目录
python scripts/sync_skill.py --list   # 只看装到哪

skill 里写死了三条铁律，避免 Agent 乱来：只转述工具返回内容；sync 有副作用（用户没要求就别跑）；库里没有就直说「没有」，不要拿网络搜索冒充收藏。

④ 装在哪、文件在哪

东西位置说明
全局命令%USERPROFILE%\.local\bin\ghstars.exe已在 PATH（macOS/Linux: ~/.local/bin/ghstars）
程序本体%APPDATA%\uv\tools\ghstars\uv 的隔离 venv，升级不污染系统 Python
源码仓库<你克隆的位置>开发/改代码在这里，uv tool install -e . 时与上面的 venv 联动
配置（唯一）%APPDATA%/ghstars/config.tomlstore 路径、分类池、LLM；不含数据
检索索引配置里 store.index 指定的位置SQLite，可删可重建
星标数据<store.dir>/github-stars/你收藏的每个项目一个 Markdown，按分类分目录
Zvec 索引知识库 .llm-wiki/知识库自带 RAG 用的，与 ghstars 索引互不干扰
两套索引不冲突，但要注意分工：知识库里 #search 走的仍是 Zvec（语义检索）； ghstars 的 SQLite 索引服务于「查 star 收藏」和外部 Agent。同步后壳脚本会把两者都更新。

⑥ 六个日常场景

场景 1：在终端查「我收藏了什么能剪视频的」

ghstars search "视频剪辑" -n 5

中文标签会命中（比如「视频剪辑」），英文项目名也能命中（如 acme/video-kit）。2 个字的词（剪辑、简历）同样有效 —— 短词走 LIKE 兜底，不需要装分词器。

场景 2：同步最新 star

# 先看差异，不写盘、不调 LLM
python3 scripts/github_stars_sync.py --dry-run

# 确认后真同步（知识库根目录下执行）
python3 scripts/github_stars_sync.py

或者在对话里发 #stars。流程：新增的项目读 README → 分类 → LLM 生成中文标签 → 写 Markdown；已取消 star 的标 type: github-star-archived（幂等，重复跑不会叠后缀）。

场景 3：在 Claude Code / Codex 里直接问

直接说人话即可，skill 会自动触发：

我之前收藏过一个自动发小红书的工具，叫什么？
我 star 的项目里有没有能做 RAG 的？

Agent 会调 ghstars search "小红书 自动发布" --json，然后基于返回的项目名/标签/描述回答 —— 不会编造。

场景 4：在 Hermes 里用（重启后）

重启 Hermes 后，工具列表里会出现 mcp_ghstars_stars_search 等 5 个工具。一句话就能用：

帮我找一下收藏里做视频自动化的项目，只要 3 个

场景 5：加一个新分类

# 1) 改配置（分类名 = 目录名）
[categories]
podcast = ["podcast", "audio", "tts"]

# 2) 让存量项目按新规则重分类（可选）
ghstars index            # 只重建索引，不动文件分类
已有文件不会自动搬家：分类只在 新增项目 时决定。要整改存量，属于手工整理范畴（移动文件后记得 ghstars index，知识库侧还要跑 entity_index.py --rebuild）。

场景 6：给别的机器装一份

uv tool install git+https://github.com/zhe97396-tech/ghstars
ghstars init && ghstars doctor

同一份 Markdown 可以放进任何 git 仓库 / 网盘同步 —— 索引是本地的，不跟着走。

⑦ 维护与升级

你想改什么改哪里怎么生效
检索 / 同步 / 分类行为src/ghstars/uv tool install --reinstall git+…
MCP 工具mcp_server.py 的 TOOLS同上 + 宿主重启
Skill 话术skills/ghstars/SKILL.mdpython scripts/sync_skill.py
版本号只改 pyproject.toml__version__ 自动跟随；再 git tag vX.Y.Z
索引结构index.py用户侧 ghstars index 重建，不做迁移

兼容性红线：Markdown frontmatter 的字段（repo / type / category / tags / topics / starred_at）是公开契约 —— 改名等于 major 版本，必须带迁移脚本。索引怎么改都行，因为它是缓存。

发布流程（三步）：改 version → 在 CHANGELOG.md 记一条 → git tag vX.Y.Z && git push --tags，然后 gh release create。

⑧ 排错

现象原因 / 解决
索引不存在首次使用或索引被删：ghstars index（或先 ghstars sync）
标签全是空 / 没有中文描述LLM 没配上：ghstars doctor 看 LLM 行；检查 config.toml 的 [llm] 与 api_key_env 指向的环境变量是否存在
MCP 宿主里看不到工具改配置后必须重启宿主；command 用绝对路径更稳（~/.local/bin/ghstars.exe）
报 ModuleNotFoundError: pydantic_core / 加载到错误 mcp宿主注入了 PYTHONPATH，用 PYTHONPATH="" 运行
Windows 控制台中文乱码已内置 UTF-8 兜底；仍异常时 set PYTHONIOENCODING=utf-8
GitHub 403 速率限制配 token：gh auth login 或 GITHUB_TOKEN（匿名只有 60 次/小时）
删了 Markdown 但还能搜到索引是缓存：ghstars index 重建
